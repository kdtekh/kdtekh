Guí­a de Git y GitHub para Desarrolladores

25 Abril 2025 6 min de lectura

Git y GitHub se han convertido en herramientas esenciales para cualquier desarrollador en la actualidad. Ya seas un programador principiante o experimentado, dominar estas herramientas mejorará significativamente tu flujo de trabajo y te permitirá colaborar de manera más efectiva en proyectos de software.

¿Cuál es la diferencia entre Git y GitHub?

Git es un sistema de control de versiones distribuido que te permite rastrear cambios en archivos. GitHub es una plataforma de alojamiento que utiliza Git para el control de versiones, además de ofrecer caracterí­sticas adicionales para la colaboración en proyectos.

1. Instalación y Configuración Inicial

Instalación de Git

Descarga e instala Git desde git-scm.com según tu sistema operativo.

Configuración Básica

Después de instalar Git, configura tu información de usuario:

# Configurar nombre de usuario git config --global user.name "Tu Nombre" # Configurar correo electrónico git config --global user.email "tu@email.com" # Establecer el editor por defecto (opcional) git config --global core.editor "code --wait" # Para VS Code # Ver la configuración git config --list

2. Conceptos Básicos de Git

Repositorio (Repository)

Un repositorio es como una carpeta para tu proyecto. Contiene todos los archivos y el historial de cambios.

# Inicializar un nuevo repositorio git init # Clonar un repositorio existente git clone https://github.com/usuario/repositorio.git

Commits

Un commit es una instantánea de los cambios en tu repositorio en un momento dado.

# Ver el estado de los archivos git status # Añadir archivos al área de preparación (staging) git add nombre-archivo.js # Archivo especí­fico git add . # Todos los archivos modificados # Crear un commit git commit -m "Mensaje descriptivo de los cambios"

Ramas (Branches)

Las ramas permiten trabajar en diferentes versiones de tu proyecto de forma aislada.

# Crear una nueva rama git branch nombre-rama # Cambiar a una rama git checkout nombre-rama # Crear y cambiar a una nueva rama en un solo comando git checkout -b nombre-rama # Ver todas las ramas git branch -a # Eliminar una rama git branch -d nombre-rama # Eliminación segura git branch -D nombre-rama # Eliminación forzada

Fusionar (Merge) y Rebase

Combinar cambios de diferentes ramas.

# Fusionar una rama en la rama actual git checkout main git merge nombre-rama # Hacer rebase de la rama actual sobre main git checkout mi-rama git rebase main

3. Trabajando con GitHub

Configuración de SSH

Para una autenticación segura sin contraseña:

# Generar una nueva clave SSH ssh-keygen -t ed25519 -C "tu@email.com" # Iniciar el agente SSH eval "$(ssh-agent -s)" # Añadir tu clave privada al agente ssh-add ~/.ssh/id_ed25519 # Copiar la clave pública para añadirla en GitHub cat ~/.ssh/id_ed25519.pub

Luego, ve a GitHub SSH keys y añade tu clave pública.

Comandos Básicos de GitHub

# Añadir un repositorio remoto git remote add origin https://github.com/usuario/repositorio.git # O con SSH (recomendado) git remote add origin git@github.com:usuario/repositorio.git # Enviar cambios al repositorio remoto git push -u origin main # Primera vez git push # Siguientes veces # Obtener cambios del repositorio remoto git pull # Obtener cambios sin fusionar git fetch

4. Flujo de Trabajo con Git

Flujo de Trabajo Básico

  1. git pull - Actualiza tu rama local con los últimos cambios
  2. git checkout -b nombre-de-rama - Crea una rama para tu caracterí­stica
  3. Realiza tus cambios en el código
  4. git add . - Prepara los cambios
  5. git commit -m "Mensaje descriptivo" - Guarda los cambios localmente
  6. git push -u origin nombre-de-rama - Sube los cambios a GitHub
  7. Crea un Pull Request (PR) en GitHub
  8. Después de la revisión, fusiona el PR

Git Flow (Flujo de Trabajo Avanzado)

Un modelo de ramificación exitoso para proyectos más grandes:

  • main/master: Código de producción estable
  • develop: Integración de caracterí­sticas
  • feature/: Para nuevas funcionalidades
  • release/: Preparación para lanzamiento
  • hotfix/: Correcciones rápidas en producción

5. Comandos Avanzados íštiles

# Ver el historial de commits git log --oneline --graph --decorate --all # Deshacer cambios locales no confirmados git restore . # Deshacer el último commit (manteniendo los cambios) git reset --soft HEAD~1 # Cambiar el mensaje del último commit git commit --amend -m "Nuevo mensaje" # Limpiar archivos no rastreados git clean -fd # Alias útiles git config --global alias.co checkout git config --global alias.br branch git config --global alias.ci commit git config --global alias.st status

6. Buenas Prácticas

  • Haz commits atómicos (un cambio lógico por commit)
  • Escribe mensajes de commit claros y descriptivos
  • No hagas commit de archivos generados automáticamente
  • Usa .gitignore para excluir archivos innecesarios
  • Haz pull antes de push para evitar conflictos
  • Revisa tus cambios con git diff antes de hacer commit

Conclusión

Dominar Git y GitHub es una habilidad esencial para cualquier desarrollador moderno. Con esta guí­a, tienes los conocimientos básicos para comenzar a trabajar con control de versiones de manera efectiva. Recuerda que la práctica constante es clave para volverte experto en estas herramientas.

¿Quieres profundizar más? Explora la documentación oficial de Git o los documentos de GitHub para aprender más sobre caracterí­sticas avanzadas.
